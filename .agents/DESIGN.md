# DESIGN.md

Design system and agent rules for the ShippersLab landing page. This is the single source of truth: for every visual decision and for how any agent (Claude, Codex, or otherwise) is expected to work in this repo. `.claude/CLAUDE.md` and `.agents/AGENTS.md` both point here instead of repeating it. The Tailwind theme (`src/styles/globals.css`) implements exactly what is written here: if they ever disagree, this file wins and the CSS gets fixed.

## Colors

| Token    | Value     | Tailwind utility (examples)         | Usage                                    |
| -------- | --------- | ------------------------------------ | ----------------------------------------- |
| `accent` | `#FE5634` | `bg-accent`, `text-accent`, `border-accent` | CTAs and a small number of accents. **Restricted: must not appear more than 5 times on the page.** |
| `ink`    | `#0B0F1A` | `bg-ink`, `text-ink`                 | Primary text.                             |
| `paper`  | `#FEFEFE` | `bg-paper`, `text-paper`             | Page background.                          |
| `muted`  | `#5F6777` | `text-muted`                         | Secondary text (4.92:1 on `paper`).        |
| `border` | `#E0E3E9` | `border-border`                      | Hairline borders.                         |
| `surface` | `#FFFFFF` | `bg-surface`                        | White card surface on `paper` (blog author card, blog short-answer box). |

No other colors are introduced without updating this table first.

### Contrast (WCAG AA)

`accent` stays the brand fill, and these rules keep every pairing at AA or better:

- Accent fills (CTAs, selected chips, completed steps, text selection) keep `paper` text as a brand decision. That pairing measures 2.75:1, below AA, and it is the one accepted exception on the page; if the team wants AA there, the fix is a darker fill token such as `#C2391D` (4.66:1 with `paper`), not grey or black text on the brand orange.
- Text selection is `accent` with `paper` text by default and flips to `paper` with `ink` text on any `bg-accent` element and its descendants (automatic in `globals.css`) and on containers that sit text over an accent image via the `selection-paper` utility (CTA, contact, /empecemos); a `bg-paper` card nested inside goes back to the default.
- `accent` is never a text color on `paper` (2.75:1), with one approved exception: the inline EventOps link in the Services section is `font-medium text-accent` with an `accent` underline, as the single proof point the page wants the eye to land on. Any other link that wants emphasis is `text-ink` with a `decoration-accent` underline. Error messages are `text-ink`; the alert icon next to them may stay `text-accent`.
- `muted` is the lightest text color allowed on `paper`.
- Every interactive element shows a visible focus ring: a 2px `ink` outline with an offset (`focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-ink`). Never use `focus:outline-none` without a replacement.

## Typography

| Role                         | Font        | Weight | Tracking   | Size                          | Line height | Tailwind utility        |
| ----------------------------- | ----------- | ------ | ---------- | ------------------------------ | ----------- | ------------------------ |
| Section titles                | Hanken Grotesk | 500    | `-0.045em` | n/a                             | 1.05        | `font-heading tracking-heading` (applied by default to `h1`/`h2`/`h3`) |
| Hero                           | Hanken Grotesk | 500    | `-0.05em`   | `clamp(40px, 6vw, 80px)`       | 0.96        | `tracking-hero text-hero` |
| Body                           | Geist       | 400    | normal     | 16–18px                        | 1.6         | `font-sans text-base` / `text-lg` |
| Labels / technical details     | DM Mono     | 500    | `0.12em`, uppercase | 11px                | 1.4         | `font-mono uppercase tracking-label text-label` |

### Text sizes and reveals (whole site)

- Description or lead right under a page or section heading: `text-base text-muted sm:text-lg`.
- Body paragraphs (rows, cards, lists): `text-base text-muted`. `text-sm` is only for secondary meta.
- Every page or section title uses `DiaTextReveal`, every description and body paragraph uses `WordReveal`, card and list groups use `StaggerReveal`, other blocks use `BlurReveal`.
- No eyebrow badge sits above the hero title on service pages and /como-trabajamos.

Nunito and Geist Pixel are not used anywhere on the landing. Hanken Grotesk (500, with 600 loaded) is the only display face, applied to every heading from the hero down to section titles through the shared `font-heading` token (default on `h1`/`h2`/`h3`). There are no `font-pixel*` utilities. Never render a heading in full uppercase with wide tracking, which reads as a label rather than a title.

A headline can pick up a subtle print-grain texture instead of a flat fill with the `text-grain` utility (`src/styles/globals.css`): it clips a noise pattern to the text using `background-clip: text`. Use it sparingly, on a single short headline at a time, never on body copy or the labels role, where texture competes with the 11px size.

## Layout

- Content max-width: **1200px** (`max-w-content`).
- Vertical section padding: **112px on desktop** (`py-section`); Team and FAQ use a tighter 80px (`md:py-20`).
- Inside a section, content groups (heading, then each following block) are separated by one shared gap: `mt-16 sm:mt-20`. Labels sit `mt-6` above the thing they label.
- Service pages and /como-trabajamos open with a centered hero (badge, title, lead) over the Dither, then every section is its own `Container` separated by `border-t border-border` inside the `max-w-content border-x border-border` frame; titles use `DiaTextReveal`, descriptions `WordReveal`, card groups `StaggerReveal`, single blocks `BlurReveal`, and there is no visual breadcrumb. The blog post hero (`variant="article"`) stays left-aligned.
- Long-form pages (service pages, the EventOps case) lay their body out as rows with the title in a left column and the content in a right column (`lg:grid-cols-[1fr_2fr] lg:gap-16`), separated by a `border-border` hairline. Below `lg` the rows stack.
- Borders are **1px**, and boxes are **never** shadowed. `shadow-*` utilities resolve to `none`; if a shape needs separation, give it a `border-border` instead.
- Border radius tops out at **8px** for boxes, cards and inputs. The `rounded-*` scale (`xs` through `4xl`) is clamped so nothing in the app can round past 8px. The only exception is `rounded-full`, allowed on choice chips, stepper dots and the team avatars in the Team section, and nowhere else.
- `accent` is a spotlight color, not a brand wash: budget its five uses deliberately across the page (the primary CTAs in the nav, hero and contact form, plus the two mid-page "talk to us" prompts that shorten the path to an email, one of them the mailto line closing the Team section); the Team section also carries a muted, non-accent marquee of the four approved former-employer logos from `ui/marquee`). Brand illustrations drawn in `accent` (the hero art) are decorative and do not count against that budget, and the navbar logo asset is exempt as the brand mark. The transient `accent` sweep of `DiaTextReveal` on every heading (hero, section titles and service titles) is exempt as well. `public/images/bandera-accent.webp` is an available decorative background (the Process section was removed from the home page). The The Contact section (`sections/contact`, currently not rendered on the home page; the CTA and FAQ buttons point to /empecemos) is a large `rounded-lg` panel on `public/images/puente-accent.webp` (Puente Colgante engraving, same treatment) with the headline and free-call line in `text-paper` on the image and a wide `bg-paper` card below holding a compact horizontal form (name and email/WhatsApp side by side, a 3-row message, the submit button aligned right) and one wrapping row of small contact links; any text placed directly on the image must be `text-paper`. It is decorative and exempt as well. The CTA panel between the FAQ and Contact (`sections/cta`) is a `rounded-lg` panel on `public/images/salto-accent.webp` (person leaping between cliffs, same treatment: lazy, quality 90, blur-in) with a `text-paper` headline, one line and a `variant="paper"` `TextureButton` linking to `/#contacto`; it is decorative and exempt. `public/images/carretera-accent.webp` (Argentine road toward mountains) and `public/images/puerto-accent.webp` (industrial port) are available decorative backgrounds of the same family, also exempt from the budget. The 404 page fills the viewport with `public/images/not-found.webp` (two unfinished bridge halves in `accent` on `paper`, `object-cover`, anchored to the bottom) and centers the title, description and CTA in the empty sky between them; it is decorative and exempt as well. The `Dither` background behind each service page hero and the /como-trabajamos hero (which reuses `ServiceHero`) (a full-bleed WebGL dither of slow waves in a muted `accent` on `paper`; on /como-trabajamos it starts below the navbar so the navbar stays on plain `paper`, low contrast, vendored from React Bits, faded out toward the bottom edge) is decorative and exempt as well; it is the only animated background on service pages and /como-trabajamos, it reacts subtly to the pointer, and it renders a single static frame under reduced motion. The FAQ help card's icon container (`bg-accent` with a `text-paper` icon, under `faq/faq-help.tsx`) is a user-requested accent fill and counts as one of the five uses. No other gradients, washes or hover states introduce `accent`.
- **Buttons are square-cornered, not pills.** CTAs use `TextureButton` with `size="square"`: `rounded-md`, label on the left and a small inset square box (`size-8`, `rounded-sm`) with an up-right arrow on the right. Primary is an `accent` fill with `paper` text and a `paper` box with an `ink` arrow; secondary is `paper` with a `border-border` hairline, `ink` text and an `ink` box with a `paper` arrow. On hover nothing moves or scales: only the fill color shifts (300ms `ease-out`); the arrow stays still. The secondary border is `border-muted/35` so it reads against `paper`. The navbar CTA uses `variant="primary"` with `size="compact"` (no icon box). `size="pill"` is legacy and only remains on secondary pages until they are migrated.
- **The hero.** `public/images/obelisco-white.webp` (`accent` engraving on white) fills a `rounded-lg` `bg-paper` card with the page side padding: no border, no shadow, `object-cover`, centered and anchored to the top (`object-top`) from `sm` up; on phones the image starts below the navbar (the white sky continues above it). Served through `next/image` with `preload`, `fetchPriority="high"`, responsive `sizes` and AVIF/WebP (`images.formats` in `next.config.ts`). It is a decorative illustration, exempt from the `accent` budget, and there is no video. The primary CTA opens WhatsApp (`wa.me` with a prefilled message, falling back to /empecemos when `NEXT_PUBLIC_WHATSAPP_NUMBER` is unset) and the secondary links to /casos. On desktop the hero fills the viewport height; below the card the title (line-height 1.02, with `pb-[0.12em]` on the reveal so descenders never clip) sits left and the description and CTAs right, all top-aligned inside `Container`. `bandera-accent.webp` and `puente-accent.webp` are available decorative backgrounds of the same kind, also exempt from the budget.
- **The navbar is fixed and turns to glass on scroll.** It is persistent chrome rendered once by the root layout: a compact, minimal bar (`rounded-md`, max `xl` wide, `fixed` at `top-4` on every route) with the `accent` logo left, three links (Servicios, Casos, Eventos) centered in `text-ink/70 hover:text-ink`, and the primary `accent` compact CTA right (the nav CTA's use in the budget). At the top of the page it has no fill and no border, so it sits on the white hero; once the page scrolls past 24px it fades (300ms `ease-out`) to `bg-paper/70` with `backdrop-blur-md` and a `border-border/80` hairline. Non-home routes get an `h-16` spacer so content starts below it; full-bleed pages (404) skip the spacer. The language switcher is not in the desktop bar; it lives in the mobile menu and the footer.
- **Services use isometric figures in tinted panels.** Each service is an alternating row (figure left or right, text on the opposite side, stacked with the figure first below `lg`). The figure sits in a `rounded-lg` panel with a soft `accent` tint (`border-accent/20`, `bg-linear-to-br from-accent/20 via-accent/8 to-paper`); the kit's plate corners are visually hidden but still feed the screen-reader readout. The text side is: a small `rounded-full` `accent` icon chip with a `paper` icon, the plain service title, a two-sentence description, a hairline-separated list of three deliverables in the body font with small `accent/15` check dots, and a secondary square "Ver más" button. No index numbers, mono tag chips or audience badge. The accent tints, icon chips and check dots are decorative and exempt from the `accent` budget, as are the isometric figures.
- **Casos list.** Centered page header, then a 2-column grid (1 on mobile) with generous gaps. Each card: a small muted category line on top, a full-width `aspect-video` `rounded-lg` image with a `border-border` hairline, then the project name and one-line summary with a plain `muted` up-right arrow to the right. No frame tabs. The image is static: no zoom, scale or transform on hover. Hover feedback lives only on the text and the arrow (it turns `ink` and nudges up-right); the whole link carries the focus ring. Below the grid, the dashed "Acá va tu caso" card carries the page's only CTA (primary square button to /empecemos). The Estacionar case page shows its cover big and static, then the other two images side by side (stacked on mobile) in a `rounded-lg` `border-border` frame, each with a one-line caption, followed by the long-form rows (idea, problem, how it works, what we built, where it stands).
- The navbar and footer are persistent chrome: they live in `src/components/layout` and are rendered once by the root layout, never by a page. A page only renders its own sections.
- The footer groups its links in titled columns (brand and tagline, Servicios, Explorar, contact with email, Instagram and X), then a hairline row with the copyright and the language toggle (a single button-looking link that navigates to the same page in the other language, Español at the root and English under `/en`, no dropdown), then a generous top margin before a giant `ShippersLab` wordmark (SVG `<text>` with `textLength`, `font-heading`, `fill-ink/10`) that spans the full `max-w-content` width with the bottom ~35% of the glyphs cut off by the page edge, so it reads as texture. It is decorative (`aria-hidden`), blurs into focus once when it enters the viewport, and does not count against the `accent` budget.

## Motion

- GSAP is the animation library. Scroll-triggered reveals go through `ScrollTrigger` (or a plain `IntersectionObserver` for the simplest cases), never through a scroll listener that runs on every frame. An element starts hidden/offset and animates to its resting state once, when it crosses the viewport threshold.
- Photographic/illustrated images resolve from a soft blur into focus (fade + `filter: blur()` to `0`) instead of scaling or sliding in. Abstract UI illustrations (the kind built from divs, not images) build themselves in with a small stagger instead. The one exception is the hero: it is the LCP element, so JS never hides it. It renders `obelisco-white.webp` with `next/image` with `preload`, `quality={100}` and `fetchPriority="high"` on every screen and resolves from blur through the CSS `animate-hero-image` keyframe (0.8s), which works before hydration. The home intro runs in one consistent sequence where every element resolves from blur with no movement: the image (0.8s), the navbar (from 0.35s, 0.8s long, same blur as the image), the title reveal (from 0.7s, 2.2s long), the description, then the primary CTA and the secondary CTA one after the other (0.8s each, 0.15s to 0.35s apart). Under reduced motion everything is visible immediately.
- Every title (page, section, CTA panel) reveals with `DiaTextReveal` and every subtitle or description right below it with `WordReveal` (per-word rise, any length). Page headers go through `PageHeader` (`ui/section/page-header.tsx`) and section headers through `SectionHeading`.
- Hovers transition over **200ms** (`duration-200`), except `TextureButton`, which uses **300ms** for color and **500ms** for the arrow nudge so CTAs feel softer, with the shared `ease-out` token, `cubic-bezier(0.23, 1, 0.32, 1)` (`--ease-out` in `@theme`). Use `ease-out` rather than ad hoc curves.
- Loading states use skeletons from `ui/skeleton`: a `bg-border` surface with a slow `animate-pulse` (off under reduced motion), never a spinner. `SkeletonImage` wraps `next/image` inside a `relative` container: the skeleton covers it until `onLoad`, then the image resolves from blur into focus (700ms, `ease-out`). The home hero and full-bleed decorative backgrounds skip it and use `placeholder="blur"` instead (`lib/blur-data.ts`). Heavy routes (blog, blog posts, case details, service pages) ship a `loading.tsx` that reuses the real `max-w-content` frame, `Container` padding and hairlines so nothing shifts when the page arrives.
- Smooth scrolling is owned by Lenis, so `scroll-behavior: smooth` is not set in CSS.
- Every animation and transition respects `prefers-reduced-motion`. `globals.css` collapses all animation/transition durations to near-zero for users who request reduced motion, and any GSAP timeline must check `window.matchMedia("(prefers-reduced-motion: reduce)")` (or `gsap.matchMedia()`) and skip straight to the end state instead of bypassing it.

## Rules

These apply to every agent working in this repo, not just UI work.

- **Eyebrows and badges are never all caps.** Labels that sit above a title or act as a badge ("Proceso", "Preguntas frecuentes") render in sentence case as written in the messages, as a small bordered badge: `inline-flex rounded-md border border-border px-3 py-1.5 font-mono text-sm tracking-tight text-muted` (add `bg-paper` over busy backgrounds), without `uppercase` or `tracking-label`. An icon inside the badge uses the same `text-muted` color as the text.
- **Never leave comments in code.** No line comments, no block comments, no JSDoc, no commented-out code. If something feels like it needs a comment, rename it or extract it into a function whose name says the surprising part.
- **Always import through the `@/*` alias.** Never write a relative import (`./`, `../`), not even for a sibling file. `@/*` resolves to `src/*` and is declared once in `tsconfig.json`.
- **Everything lives in a folder that says what it is.** Each landing section is a folder in `src/components/sections` (for example `sections/hero/index.tsx`, with its own subparts next to it), reusable primitives go in `src/components/ui`, persistent chrome shared by every route (navbar, footer, wordmark) goes in `src/components/layout`, cross-cutting helpers in `src/lib`, copy in `src/i18n/messages`. Don't drop a component or helper loose in `src/app` or `src/components`.
- **No file exceeds 300 lines.** Split into a folder of smaller files before it gets there.
- **Agent configuration lives in subfolders, never loose in the project root.** This file, skills, and any future agent docs live under `.agents/` or `.claude/`. The root `AGENTS.md` is the one exception: Next.js's dev server owns and regenerates it in place, so it cannot be relocated.
- **Commits are conventional, one line, no body:**

  ```
  feature(topic): short description
  ```

  No description beyond the subject line, no bullet list, no "Co-authored-by" line. `topic` is the area touched (`hero`, `pricing`, `i18n`, `design`, …). `commitlint` enforces the allowed types on every commit via a git hook.

## Source of truth

Tailwind tokens live in `src/styles/globals.css` under `@theme inline`, and font loading lives in `src/lib/fonts.ts`. Component-level styling uses these tokens through Tailwind utilities only. No inline styles, no ad hoc hex values, no arbitrary values (`w-[13px]`) when a token already covers the case.

## Brand assets

Logos, avatars, and social graphics are maintained in the separate `shipperslab-brand` repository, not here. When a brand asset is needed in the landing page, copy the exported file into `public/images` (content) or `public/icons` (icons, favicons). Never reference the sibling repo's path directly, since it won't exist in deployment.
